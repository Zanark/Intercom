Intercom / honest product review / 12 November 2026

The pieces exist.
The experience is not there yet.

You wanted to talk to Copilot and watch it work through your contexts. We have built useful parts, but we have not delivered that as one consistently fast, convincing, shipped experience.

Your criticism is fair.

A longer recorder and an attractive sphere do not, by themselves, make a voice-first Copilot overlay. The next milestone should prove the complete interaction, not add another isolated setting.

01 / What you expected

Speak. Copilot works. The mesh shows why.

The sphere is not just decoration. It should help you understand what Copilot is actually using. Speech quality and response speed are the entry gate; the live mesh is the distinctive experience.

02 / What we actually have

Real building blocks, unevenly connected.

BUILT, WITH LIMITS

On-device recognition

Included local Whisper/Vulkan recognition, microphone capture, editable transcripts, cancellation and optional live drafts exist. Your supplied recordings have exercised the actual native recognizer.

That establishes operation, not human-accepted English/Hinglish accuracy. Live drafts are repeated batches, not word-by-word streaming.

BOUNDED LIVE PROOF

Existing-session dispatch

Actual requests have reached a designated existing idle session. Responses, identity checks and owned transport cleanup are real. A separate approved read-only operation was also exercised.

This is not proof of arbitrary work across all sessions. Busy sessions remain protected; genuine permission prompting still needs broader live qualification.

PARTIAL OBSERVABILITY

A real mesh, not a full activity stream

The app loads the actual local Context Mesh snapshot. Job messages and tool-reported file locations can light context spokes.

A snapshot is a map. It does not say which note Copilot is reading now, and the current projection does not tell that story in sequence.

NEWER SOURCE ONLY

Research reports and longer capture

Saved-context discovery can read allowed notes and indexed histories, build a cited local report and open it. Five-minute recording support is also implemented.

Neither is in the retained .15 executable. Research summaries are extracted passages, not a Copilot-written explanation of the combined evidence.

03 / The biggest visual gap

We show activity membership, not the journey.

A concrete missing wire:

The saved-context reader currently sends its finished evidence back as one worker result. Those individual reads do not enter the graph's activity input. Meanwhile, the moving tracer is enabled only in explicit demo mode. So a real research request can read many sources while the sphere fails to tell that story.

Even where tool locations are available, a reported location is not automatically proof of a read. The current context set also accumulates during the job; it is not a timestamped read-by-read playback.

05 / Why voice still feels slow

Longer recording is not faster conversation.

The current recognizer starts a native recognition process for a complete WAV request. Optional live drafts repeatedly recognize the accumulated buffer, one batch at a time. There is no persistent warm recognition worker or true incremental streaming in this implementation.

These are individual observations on this machine, not latency guarantees, controlled benchmarks or independent accuracy scores. Legacy Windows recognition completed the long test but badly garbled the recorded speech.

The next optimization must attack the actual delay.

Measure end-of-speech to useful response, distinguish recognition from routing and work, then qualify warm/incremental recognition and remove redundant processing. Switching desktop frameworks alone would not demonstrate a fix.

The core vision is feasible. Omniscience is not.

One architectural distinction matters: the current tool-free interpretation controller sees bounded catalog/context metadata. It routes requests; it does not read all the project notes and reason over them itself. A separate host reader produces the research report. The existing working Copilot session should remain the place that performs authorized work, not be replaced by a routing helper.

07 / The smallest slice worth calling a success

One compelling loop, in the EXE you actually use.

Suggested next acceptance scenario: ask by voice for a summary of one project's saved contexts, see the actual accesses, get a clear illustrated report and hear a useful explanation. Use one designated existing idle session where agent synthesis/work is required.

Make speech the release gate.

Use your consented recordings plus natural short/long and mixed-language cases. Check names, negations and intended tasks against an independently reviewed reference. Measure latency; do not infer accuracy from successful completion.

Connect real reads to the sphere.

Show listening, transcribing, dispatching, observed context access and response as distinct states. Animate only supported events; explain unavailable telemetry instead of leaving a mysterious idle-looking graph.

Deliver an actual explanation.

Use cited evidence for what each context contributed and how the work relates. Clearly distinguish saved claims, observed actions and unresolved sources. Open the report and speak a concise useful result.

Package and qualify that exact build.

Use a distinct candidate identity and disposable profile. Verify the whole voice-to-result path, interruption, cancellation and busy/permission failures. Keep your running instance untouched until a coordinated switch.

This is a proposed recovery milestone, not completed implementation, human acceptance, an ETA or authorization for new session/tool access. Individual-file visualization, wake word, a host rewrite and richer voice styling are not prerequisites for this slice.

08 / Bottom line

We optimized pieces before proving the feeling.

The safety, connector, recognition and rendering work is useful. But separate technical passes and visual polish were not a substitute for one fast, observable, delivered voice interaction. The integrated milestone is still open, and your experience is evidence that it should stay open.

Keep: local audio, existing-session identity, manual permissions, the real mesh and useful completion receipts.

Fix next: perceived speech latency, source-to-EXE delivery, context-access telemetry and a grounded result in one continuous interaction.

Do not fake: graph activity, session coverage, speech accuracy or task success.
